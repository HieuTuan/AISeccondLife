# SecondLife AI Pricing: Canonical Dataset Schema Specification

**Project:** SecondLife AI Pricing  
**Document Version:** 1.0.0  
**Target Architecture:** Multimodal Feature Extraction (PhoBERT Text + CLIP Vision + Tabular Features + Regression Head)  
**Target Market:** Vietnam Secondary Appliance Market  
**Target Currency:** Vietnamese Dong (VND)  

---

## 1. Overview & Objectives

The SecondLife AI Pricing platform requires a standardized, multimodal dataset schema to train machine learning models that estimate fair listing prices for pre-owned household appliances.

To prevent data contamination, model bias, and legal non-compliance, this schema establishes:
1. **Multimodal Co-Registration:** Guaranteed association between physical condition photos, Vietnamese descriptive text, and tabular specifications.
2. **Strict Validation & Boundary Constraints:** Realistic boundaries for Vietnamese Dong (VND) listing prices and appliance operational ages.
3. **Data Provenance & Source Traceability:** Explicit tracking of dataset lineage, upstream record identifiers, and licensing rights.
4. **Group-Level Partitioning Metadata:** Structural keys to prevent duplicate-listing leakage during train/validation/test splits.

## 2. Canonical Schema Definition

| Field Name | Type | Nullable? | Validation Rules & Constraints | Description & Example |
|:---|:---:|:---:|:---|:---|
| `listing_id` | `string` | **No** | Unique primary key. Pattern: `^[A-Za-z0-9_-]{6,64}$`. | Unique SecondLife listing identifier. e.g. `SLVN-2026-000189` |
| `title` | `string` | **No** | Min 5 chars, max 255 chars. Non-empty, valid text. | User/listing title in Vietnamese. e.g. `"Tủ lạnh Panasonic Inverter 255L còn mới 95%"` |
| `description` | `string` | Yes | Max 5,000 chars. Cleaned UTF-8 string. | Detailed description of features and condition. e.g. `"Máy chạy êm, làm lạnh nhanh, nguyên zin"` |
| `category` | `string` | **No** | Must match one of the 16 canonical categories (Enum). | Canonical category name. e.g. `Refrigerator`, `Washing Machine` |
| `brand` | `string` | **No** | Min 2 chars, max 64 chars. Uppercase normalized. | Manufacturer brand name. e.g. `PANASONIC`, `TOSHIBA`, `ELECTROLUX` |
| `model_number` | `string` | Yes | Max 64 chars. Alphanumeric / dashes. | Manufacturer model code if known. e.g. `NR-BL300PKVN` |
| `condition` | `string` | **No** | Must match one of 5 standard condition tiers (Enum). | Physical and functional grade: `Like New`, `Excellent`, `Good`, `Fair`, `Poor` |
| `age_years` | `float` | Yes | If provided, must satisfy `0.0 <= age <= 30.0`. | Estimated age of the appliance since manufacture/purchase. e.g. `2.5` |
| `image_paths` | `list[str]` or `json` | **No** | Minimum 0 images for text-only baselines, >= 1 for multimodal. | Relative local file paths to verified RGB images. e.g. `["images/3354718/img1.jpg"]` |
| `listing_price_vnd` | `float` / `int` | **No** | `50,000 <= price <= 150,000,000`. Finite positive number. | Active asking price in Vietnamese Dong (VND). e.g. `4500000` |
| `initial_listing_price_vnd` | `float` | Yes | Original unprompted asking price. | **Primary ground truth regression target** before AI appraisal. e.g. `4500000` |
| `ai_suggested_price_vnd` | `float` | Yes | AI recommendation shown to seller. | Prediction generated by SecondLife AI. **Never used as training label.** |
| `user_adjusted_price_vnd` | `float` | Yes | User counter-offer after seeing AI price. | Price adjusted by seller after reviewing suggestion. |
| `transaction_price_vnd` | `float` | Yes | Realized deal price upon completion. | Actual closed transaction price. |
| `product_group_id` | `string` | Yes | Group cluster key for data splitting. | Identifier preventing multi-view or re-listing leakage across splits. |
| `physical_item_id` | `string` | Yes | Unique physical pre-owned unit identifier. | Distinguishes individual physical units from manufacturer model numbers. |
| `listed_at` | `string` | Yes | ISO 8601 formatted datetime string (`YYYY-MM-DDTHH:MM:SSZ`). | Timestamp when the listing was created/scraped. |
| `source` | `string` | **No** | Allowed: `secondlife_partner`, `chotot_partner`, `facebook_partner`, `user_submission`, `synthetic_benchmark` | Upstream data origin channel. |
| `source_record_id` | `string` | Yes | Max 128 chars. Lineage identifier. | External record ID in source system for traceability. e.g. `CT-1094821` |
| `license_status` | `string` | **No** | Allowed: `authorized_partner`, `public_domain_cc0`, `synthetic_test_only`, `unlicensed_blocked` | Licensing and compliance authorization status. |
| `permission_evidence` | `string` | Yes | Max 255 chars. Legal audit proof. | User consent log ID or B2B partner contract ID under Decree 13/2023/ND-CP. |

## 3. Allowed Enumerations & Controlled Vocabularies

### 3.1 Appliance Categories (16 Canonical Classes)
The SecondLife category hierarchy maps directly to the audited appliance taxonomy:
1. `Air Conditioner` (Điều hòa / Máy lạnh)
2. `Beer Fridge` (Tủ ướp bia / Cervejeira)
3. `Dishwasher` (Máy rửa bát / chén)
4. `Dryer` (Máy sấy quần áo)
5. `Food Processor` (Máy xay / chế biến thực phẩm đa năng)
6. `Freezer` (Tủ đông)
7. `Microwave` (Lò vi sóng)
8. `Oven` (Lò nướng)
9. `Refrigerator` (Tủ lạnh)
10. `Stand Mixer` (Máy trộn / nhào bột)
11. `Stove` (Bếp gas / Bếp từ / Bếp hồng ngoại)
12. `Washer Dryer` (Máy giặt sấy kết hợp)
13. `Washing Machine` (Máy giặt)
14. `Water Dispenser` (Cây nước nóng lạnh)
15. `Water Purifier` (Máy lọc nước)
16. `Wine Cooler` (Tủ bảo quản rượu vang)

### 3.2 Condition Tiers
Pre-owned appliances are graded into five standardized tiers:
- **`Like New` (Như mới - 99%):** Flawless appearance, minimal operation, includes original manuals/packaging, no cosmetic blemishes.
- **`Excellent` (Rất tốt - 90-95%):** Fully functional, minor unnoticeable hairline scuffs, pristine internal components, well-maintained.
- **`Good` (Tốt - 80-89%):** Fully functional, noticeable surface scuffs or slight discoloration, no structural impact on cooling/heating/washing.
- **`Fair` (Khá - 70-79%):** Fully functional but significant cosmetic wear (minor dent, paint chipping, visible rust spots), missing minor accessory (e.g. ice tray).
- **`Poor` (Cũ / Cần bảo dưỡng):** Operational defects or heavy wear (loud motor, dented frame, heavy rust, cooling inefficiency); valued primarily for parts or heavy refurbishing.

### 3.3 Licensing and Provenance Status
- **`authorized_partner`:** Acquired under a formal corporate data-sharing agreement with verified rights. Fully approved for model training.
- **`public_domain_cc0`:** Publicly released under verified CC0 / MIT / Apache-2.0 licenses with commercial rights.
- **`synthetic_test_only`:** Synthetic benchmark data generated strictly for pipeline unit tests and validation mocks. **Never included in real model training.**
- **`unlicensed_blocked`:** Scraped or harvested without legal authorization. **Strictly rejected by the validation pipeline.**

## 4. Validation Rules & Data Integrity Checks

The automated validation engine (`src/data/pricing_validation.py`) enforces the following validation stages:

### 4.1 Price Boundary Validation
- Minimum allowable price: **50,000 VND** (~$2.00 USD). Prices below 50,000 VND represent placeholder listings (e.g. "1 đ", "0 đ" used by sellers to attract chat messages).
- Maximum allowable price: **150,000,000 VND** (~$6,000 USD). Prices above 150,000,000 VND represent luxury commercial installations or data entry typos (extra zeros).

### 4.2 Outlier Detection Mechanics
To prevent erroneous listings from corrupting loss functions during regression training, two complementary outlier detection methods are computed per category:
1. **Interquartile Range (IQR) Fences:**
   $$\text{Lower Fence} = \max(50,000, Q_1 - 1.5 \times \text{IQR})$$
   $$\text{Upper Fence} = Q_3 + 1.5 \times \text{IQR}$$
   Listings falling outside these fences are flagged for human inspection (`is_price_outlier = True`).
2. **Extreme Outlier Fences ($3.0 \times \text{IQR}$):**
   Listings beyond $3.0 \times \text{IQR}$ are automatically quarantined.

### 4.3 Deduplication & Leakage Prevention
Second-hand marketplaces suffer heavily from seller re-posting (re-listing the same item every 3 days to stay at the top of search feeds).
- **Exact Duplicate Check:** Rows with identical `source_record_id` or identical `(title, brand, category, listing_price_vnd)`.
- **Image Duplicate Check:** Listings sharing identical image file hashes or image paths with conflicting prices are flagged as suspicious.
- **Product Group Key (`product_group_id`):** For data splitting, listings representing the same physical item or SKU are grouped together. The `DataSplitter` partitions clusters into disjoint sets so no product instance or multi-view photo leaks across train and test sets.

## 5. Storage Formats

- **Tabular Metadata:** Stored as Apache Parquet (`.parquet`) with Snappy compression for production training, and CSV (`.csv`) for human audit inspection.
- **Images:** JPEG or WebP format, minimum resolution $224 \times 224$ px, RGB color mode, stored in structured subdirectories named by `listing_id` or `interaction_id`.
